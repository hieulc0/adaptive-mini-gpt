## Prespecified concept feasibility

See `data/specs/concept_binding_v1.json`. Research simulator `data/concept_binding.py` constructs paired observations with identical word multisets and opposite state labels by swapping which entity owns which properties. It is never used as a deployed reasoning engine. Language inference uses only complete text and the supplied last-action category; structured property/law/parity inputs go exclusively to the separately labelled diagnostic oracle MLP.

Train/test hold out joint two-entity property relationships, names and description syntax. Individual property bundles, trait words and two law schemas are familiar; this is not novel-rule/vocabulary transfer. One/two action toggles are commutative, so success would not prove noncommutative action-order reasoning. Two traits are independently crossed; the remaining24 attribute logits are outside the world's trait inventory and have no positive labels. All metrics must be interpreted as a two-trait study, not broad26-class extraction.

A fixed seed42,200 tiny updates and800 main updates are declared before any held-out score. Compare frozen/selective/full existing students, majority, BoW linear/MLP, word1–3-gram linear and structured diagnostic MLP. All trainable arms use the same observations/steps/minibatch stream; actual compute/capacity is reported separately. Validation is monitored at100-step intervals without checkpoint selection; test descriptions and compositions are evaluated once at the fixed endpoint. Tiny fit failure stops the neural arm. No learning-to-learn or learned-controller claim is possible from this single feasibility study. Negative results stop further learning complexity.
